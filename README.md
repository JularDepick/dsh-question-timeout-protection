一旦 ask_user_question 超时且留有草稿, 草稿会保留在该次提问的气泡里; 注入开启时它随工具的 pending 返回值一起交给模型。已超时的问答卡片由插件收起, 宿主原版的「回答」入口不再出现。

## 功能

- 右上角倒计时: 问答对话框右上角显示本次问答的剩余等待时间,并随剩余时间递减
- 临近超时警示: 剩余时间进入警示秒数(默认 5 秒)时红字闪烁
- 无限等待: 正在进行的问答在倒计时右侧显示「无限等待」按钮, 点击后倒计时冻结并显示「已暂停」, 直到用户提交才结束; 历史提问与已结算回答的只读卡片不显示倒计时与这个按钮
- 选中底色: 单选题选中后, 选项前的方形按钮填充底色
- 提问标识气泡: 只在超时并把草稿记入内存后, 于提问工具调用处出现一个气泡按钮, 点开在气泡旁弹出只读悬浮卡片查看该次草稿; 宿主自带的「回答」气泡与它功能冲突, 由插件气泡统一承接
- 超时草稿保存: 问答超时后把已选选项与已输入内容保存到内存
- 上下文注入: 默认开启,超时前把草稿快照交给服务端,到期时随工具的 pending 返回值按题带回模型上下文,每题带自己的已选与补充;超时语义由同一个 pending 结果说明,模型须在回复末尾告知用户出现过提问超时以及对该草稿的处理与决策
- 草稿记入气泡: 超时后把草稿记入对应提问工具处的气泡按钮,点击在气泡旁弹出只读悬浮卡片,该次提问不再提供作答入口
- 超时收尾: 有草稿时注入开启则草稿随工具返回值交给模型、卡片由插件收起, 注入关闭则只收起卡片; 超时那一刻没有任何选择与输入(草稿为空)时同样由插件把卡片关闭, 不留下答不了的对话框
- 不做兜底继续回答: 已超时的问答不提供继续回答的兜底

## 功能立场

本插件只做一件事: 让提问的等待过程可见、可暂停,并且超时不丢内容。以下列出边界,便于判断某个需求是否属于本插件。

**做什么**

- 让等待时长可见: 在问答对话框右上角显示本次问答的倒计时,临近超时红字闪烁
- 让等待可暂停: 在倒计时右侧提供「无限等待」按钮,点击后本次问答的倒计时暂停,直到用户提交才结束
- 让提问可辨识: 给单选选中态加方形底色; 超时并记录草稿后, 在提问工具位置加提问标识气泡
- 让超时不丢内容: 把已选选项与已输入内容保存到内存,并记入该次提问的气泡供只读查看
- 按配置把超时草稿送进上下文: 超时前把草稿快照交给服务端, 到期时随工具的 pending 返回值按题带回草稿本身, 不夹带任何附加文本; 超时说明同样只出现在工具的 pending 结果里, 是否重新提问由模型决定

**不做什么**

- 不接管宿主卡片的渲染与文案: 只在其 DOM 上做增强,隐藏宿主自带的倒计时与收起/展开控件,不改写宿主文案
- 不修改用户的预设: 通过在 agent 作用域注册同名工具就近遮蔽,用户无须改预设
- 不替用户作答: 超时不会自动勾选任何选项,也不会把草稿当成正式回答提交
- 不替模型决策: 是否重新提问、如何处理草稿由模型决定,插件只负责把信息送到位
- 不兜底继续回答: 插件接管超时的那些问答一律收起卡片并隐藏宿主的「回答」入口(超时草稿兜底关闭或「无限等待」上报失败时除外, 那时交给宿主原版处理)
- 不做持久化: 草稿只保存在客户端内存里, 插件不落盘; 刷新后气泡与草稿记录都会丢, 仍在等待的提问会重新评估并在满足接管条件时处理, 已结算的行不回显
- 不新增自定义 RPC 或存储: 草稿只经工具的返回值回到模型, 状态同步只用宿主同源路由与回环 HTTP 端点

## 机制

- 宿主默认使用阻塞式提问,提问不会超时;本插件在 agent 作用域注册同名的 `ask_user_question`,以就近遮蔽接管提问等待,不需要改动你的预设
- 超时由插件自己计时: 宿主卡片在客户端接管或开始编辑回答时会暂停自己的定时器,插件用同一时长再赛跑一次,保证到期一定返回 pending 并进入兜底流程(用户点过「无限等待」时改为继续阻塞)
- 工具走宿主的 timed 等待: 卡片与选项由宿主界面提供;倒计时由插件自绘在卡片右上角,按插件自己的截止时间渲染,聚焦或编辑都不会让它暂停;模型应当显式传等待秒数, 漏传时使用插件配置里的等待时长, 仍然按限时提问处理;模型传 `-1` 表示这次必须由用户回答, 走宿主阻塞提问, 不启用倒计时与超时兜底
- 客户端适配器只增强宿主卡片的 DOM: 插入自绘倒计时与「无限等待」按钮、给单选选中态加底色、在提问工具行插入气泡按钮;提问进行中就把草稿快照持续上报给服务端, 超时后把草稿存在内存里并收起卡片, 草稿由工具的返回值交给模型;注入关闭时只收起卡片, 不上报草稿;草稿为空时同样由插件关闭卡片
- 配置由客户端经宿主 `configForms` 服务实时读取,因此在插件详情页改动勾选立即影响行为,不需要保存或刷新

## 兼容性

- dsh: `>=0.2.1-rc.1 <=0.2.1-rc.3`
- 运行时: Node.js >= 20

尚未发布到 npm;可从本仓库构建后以包目录或 tarball 安装:

## 配置

配置页位于**插件详情页顶部**的插件级配置区块,不在「包含的组件」里;其中只有「注入到上下文」一个勾选可以调整,其余能力随插件启用状态固定生效,列表中只做说明。

| 配置项 | 取值 | 默认值 | 界面 | 说明 |
|:---:|:---:|:---:|:---:|:---|
| `fallback` | `ui` / `context` / `both` | `both` | 可改一项 | 超时兜底;界面只给「注入到上下文」勾选,默认勾选,勾上写 `both`,不勾写 `ui`。界面保留草稿恒定开启,所以不会再出现 `context`。勾选变化即写入,无需保存 |
| `cardEnhancements` | 布尔 | `true` | 固定特性 | 界面增强: 右上角倒计时与警示闪烁、单选选中底色、提问标识气泡; 只影响界面装饰, 超时接管与注入由 `draftFallback` 决定 |
| `infiniteWait` | 布尔 | `true` | 固定特性 | 提供倒计时右侧的「无限等待」按钮, 点击后本次问答倒计时暂停, 直到用户提交 |
| `draftFallback` | 布尔 | `true` | 固定特性 | 超时接管总开关: 关闭后完全不接管、交还宿主原版路径; 开启时按兜底范围把草稿交给工具返回值或只收起卡片, 草稿为空时关闭卡片 |
| `warningSeconds` | 数字 | 5 | 不暴露 | 进入红字闪烁警示的剩余秒数 |
| `timeoutSeconds` | 数字 | 120 | 不暴露 | 模型没有显式传等待秒数时使用的等待时长, 取值 1 至 2147483 秒 |

> 界面保留草稿是必选行为: 超时后草稿总留在内存里,并记入该次提问工具处的气泡按钮,点击气泡会在其旁边弹出只读悬浮卡片。勾选「注入到上下文」(默认开启)时,插件在提问还没超时就上报草稿快照给服务端,到期时草稿随工具的 pending 返回值按题带回模型上下文,卡片由插件收起;取消勾选时插件只收起卡片,不上报也不提交任何内容。超时说明与草稿都在同一个 pending 结果里,提示该轮提问已超时、用户没有正式提交,并要求模型在最后告知用户超时与对该草稿的处理决策。已超时的问答一律收起卡片并隐藏宿主「回答」入口, 不再提供继续回答的入口; 草稿为空时同样由插件关闭卡片; 兜底关闭或「无限等待」上报失败时不交草稿也不收卡片, 该轮仍按超时结算, 卡片保持可继续作答。

## 已知限制

- 依赖宿主界面结构: 卡片与工具行靠宿主类名后缀、`data-question-key`、`data-chat-call-id`、`aria-checked` 等特征定位, 宿主控件按中英文标签识别; 宿主改动这些结构或文案时对应增强会静默失效, 需要同步 `src/constants.ts`
- 不做持久化: 草稿只在客户端内存里, 刷新后气泡与草稿记录都会丢, 仍在等待的提问会重新评估并在满足接管条件时处理, 已结算的行不回显
- 「无限等待」优先走与界面同源的路由; 宿主没有注册该路由时退回本机回环端口, 此时浏览器与服务端不在同一台机器、端口被占用或有第二个 dsh 实例会导致该能力不可用, 倒计时位置会显示「无法无限等待」, 这次问答交还宿主原版处理, 不会按超时提交草稿
- 自行计时会留下宿主未结算的前台等待: 每次插件接管等待都会让宿主的等待持续到请求结算或客户端断开, 长会话下会累积
- 多标签页同时打开同一会话时, 先提交的一方生效, 另一方会因宿主拒绝重复回复而收起卡片
- 草稿快照只保留最近 200 条, 更早的气泡不再可点开
- 没有网页客户端的 profile 不启动状态同步端点, 「无限等待」在该部署下不可用
- 只是点了「跳过」而没有任何选择与输入时, 草稿按空处理, 这次超时由插件关闭卡片
- 宿主草稿不可读而只能读卡片时, 已选标签取的是宿主给读屏用的文案, 其中的「(推荐)」这类后缀可能被省略
- 注入开启但草稿快照没有送达服务端时(页面未打开、状态通道不可用、上报失败), 模型只会收到超时说明, 拿不到草稿内容; 界面上的草稿气泡不受影响
