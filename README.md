dsh提问超时保护插件: 一旦模型提问超时,将你的回答草稿保留在UI或上下文中,而不是直接丢弃.

## 为什么需要它

dsh 默认的提问是阻塞式的: 模型问完就一直等, 你离开一会儿, 整个对话就停在那里. 换成限时等待之后又出现另一个问题, 时间一到, 你已经选好, 已经写了一半的内容会被直接丢掉, 模型只知道「超时了」, 不知道你想说什么.

这个插件补上三件事: 让你看见还要等多久, 让你能暂停等待, 让超时那一刻的内容不丢.

## 它能带来什么

| 能力 | 你会看到什么 |
|:---:|:---:|
| 倒计时 | 问答卡片右上角显示还剩多少秒, 逐秒递减 |
| 临期预警 | 最后几秒数字变红闪烁, 提醒你尽快作答 |
| 无限等待 | 倒计时旁的按钮, 点一下就没有截止时间, 直到你提交或页面与会话结束 |
| 自动无限等待 | 工具栏上的常开开关, 开启后每条提问都自动进入无限等待 |
| 选中视觉 | 单选题选中后, 选项前的方形标号填充底色 |
| 超时草稿 | 超时那一刻的已选选项与已输入内容被保存下来 |
| 超时后仍可回答 | 默认保留宿主原生的「回答」入口, 你超时后补交的答复会作为一条用户消息送达模型 |
| 草稿回看 | 超时后提问行出现气泡按钮, 点开只读查看当时写了什么(宿主入口不可用时才出现) |
| 注入上下文 | 开启后草稿随工具结果回到模型上下文, 模型能接着处理 |

## 安装

### 前置条件

- dsh 版本落在 `>=0.2.1-rc.1 <0.2.2-rc.0 || >=0.2.2-rc.0 <0.2.3-rc.1` 之内, 不满足会被安装与启动阶段拒绝
- Node.js >= 20

### 方式一: 从 npm 安装

dsh 原生支持从 npm 安装插件:

```
dsh plugin --profile <profile> add dsh-question-timeout-protection
```

按包名安装取 npm 上 latest 标签指向的版本(当前是 0.2.2). 0.1.2 及更早版本声明的 dsh 上限不高于 `0.2.2-rc.2`, 在 dsh `0.2.2-rc.3` 起的宿主上会被安装与启动阶段拒绝, 需要这类旧版本时用 `dsh plugin --profile <profile> add dsh-question-timeout-protection@<版本>` 固定. 0.1.3 起支持到 `<0.2.3-rc.1`; 0.2.0 起改用与下面兼容性小节相同的两段范围, 覆盖 `0.2.2-rc.x` 与 `0.2.2` 正式版. 0.2.1 与 0.2.2 同样可以按 `@版本号` 固定, 或按下面的方式二至方式四从源码或 tarball 安装.

### 方式二: 从源码构建后安装

适合从这个仓库直接使用:

```
pnpm install
pnpm pack
# 二选一, 用相对路径或绝对路径其中一种
dsh plugin --profile <profile> add ./release/<tarball>
dsh plugin --profile <profile> add <绝对路径>
```

`pnpm pack` 会先构建, 完成后把 tarball 移入仓库根目录的 `release/`, 文件名形如 `dsh-question-timeout-protection-0.2.2.tgz`. 沙箱内生命周期脚本被拦截时改用 `pnpm run pack:release`, 产物相同. `add` 的路径要以 `./` 或 `../` 开头才会按你执行命令的目录解析, 不带前缀会被当成包名去查注册表.

### 方式三: 直接从 GitHub 源码安装

把包名换成 `github:JularDepick/dsh-question-timeout-protection#<提交>`, 由 `prepare` 负责构建.

pnpm 10 及以上默认拦截依赖的构建脚本, 因此首次 `add` 会失败并打印一个包键. 把该包键写进这个 profile 的 `pnpm-workspace.yaml` 里:

```
allowBuilds:
  dsh-question-timeout-protection: true
```

`allowBuilds` 从 pnpm 10.26 起可用; 更早的 10.x 请把同一个包键写进 `onlyBuiltDependencies` 列表.

然后重新执行 `add`. 跳过这一步装上去没有构建产物, 插件不会工作.

### 方式四: 从 Release 的 tarball 安装

下载对应版本的 tarball 后直接:

```
# 二选一, 用相对路径或绝对路径其中一种
dsh plugin --profile <profile> add ./release/<tarball>
dsh plugin --profile <profile> add <绝对路径>
```

这种方式不需要构建, 也不受 pnpm 构建脚本拦截影响.

## 快速开始

1. 按上面任一方式把插件装进你的 profile
2. 重启 dsh
3. 让模型问你一个问题, 卡片右上角会出现倒计时; 想暂停就点旁边的「无限等待」

## 使用说明

### 倒计时与临期预警

倒计时只在**正在进行的提问**上出现, 按插件自己的截止时间走, 你聚焦输入框或开始打字都不会让它暂停. 截止时间取自模型调用提问工具时传的顶层 `timeout`(秒); 没传时用本插件的 `timeoutSeconds` 配置(默认 120 秒). 写成题目对象内部的 `timeout` 属于误用, 插件只在顶层缺省时兼容读取题目里的第一个合法值(`-1`, `0` 与小数会被跳过). 剩余时间进入警示秒数时数字变红闪烁; 到了截止时间, 插件撤下自己的倒计时与故障提示, 把卡片还原成宿主自己的等待状态, 结算回执到达后统一收尾: 卡片一律撤座收起, `allow` 模式(默认)保留宿主「回答」入口与等待提示, 你仍可回去作答, `block` 模式另外隐藏该入口.

历史提问与已结算回答的只读卡片上不会出现倒计时.

### 无限等待

倒计时右侧的「无限等待」按钮, 点击后本次提问不再有截止时间, 倒计时冻结为「已暂停」, 直到你提交才结束.

点击后界面立即冻结倒计时, 同时向服务端登记这次「无限等待」; 登记失败或回执超时时撤回冻结, 不再冻结, 宿主继续计时, 倒计时位置改为显示「无法无限等待」, 这一轮交还宿主.

### 自动无限等待

工具栏模型选择控件左侧有一个常开开关「问答自动无限等待」. 开启后, 每一条新提问都自动进入无限等待, 正在等待的那条也会立刻冻结, 效果与手动点一次「无限等待」相同.

开关状态存在浏览器本地, 刷新后保留. 关闭开关只影响之后的新提问, 已经冻结的提问不会恢复倒计时, 仍由你提交结束. 多个标签页开着同一会话时, 在其中一个页面切换开关, 其他页面会在下一次界面扫描时跟上, 正在等待的提问也会随之冻结.

这个开关只在卡片增强与无限等待都开启时出现.

### 超时后仍可回答

超时只结束这一轮提问, 不等于这道题被永久关闭. 默认情况下插件保留宿主原生的「回答」入口与「已继续工作, 仍可回答」提示: 卡片照旧被收起(否则它会占住消息输入区), 但你随时可以点提问行上的「回答」重新打开它并提交, 这份答复会作为一条用户消息送达模型.

收起是稳定的: 插件自己记着哪些卡片已经收起, 切换会话(包括切到子代理会话再切回来)或刷新页面之后, 宿主重新渲染出卡片时插件会再次把它收起, 卡片不会自己弹开, 只有你点提问行上的「回答」才会重新打开. 你自己点卡片上的关闭按钮收起的卡片同样保持收起, 规则一致.

取消勾选「超时后仍可回答」后, 插件会收起卡片并藏掉宿主入口与等待文案, 这一轮不再接受作答; 模型的超时说明也会改成「已按超时后不再作答处理」的说法, 不会再让你回去补答.

这一项的取值在每次提问超时结算的那一刻定下: 之后改设置只影响新的提问, 已经按某一种方式结算过的问答不会因为改动而变脸, 你正在补答的内容也不会被当场收走.

### 超时草稿与只读回看

超时那一刻, 插件会把你已经选中的选项与已经输入的内容保存到内存. 宿主的「回答」入口不可用时, 该提问的工具调用行会出现一个气泡按钮, 点开就在气泡旁边弹出只读悬浮卡片, 按题展示当时的已选与补充; 面板本身不提供作答入口, 要补答得走宿主那张卡片.

这个气泡是兜底入口: 宿主的「回答」入口可用时由宿主承接, 气泡不出现; 「超时后仍可回答」关掉后宿主入口被隐藏, 或界面语言不是中文或英文导致插件认不出宿主入口时, 由气泡承接只读回看. 草稿为空, 也就是你什么都没选也没写时, 不产生气泡.

草稿只存在内存里, 刷新页面后气泡与记录都会消失.

### 单选题: 选项与自定义回答

宿主的单选题把"输入框里有内容"当成选中了自定义回答, 因此预设选项和自定义内容无法同时成立, 点选项还会清空已输入的内容. 插件改成显式选择: 在自定义输入框左侧挂一枚与预设选项同地位的单选按钮, 是否选中自定义只看这枚按钮, 不看输入框里有没有字.

- 选中自定义时: 预设选项的选中底色被压掉, 提交的就是自定义内容, 已选为空
- 选中某个预设选项时: 已输入的自定义内容不会丢, 输入框下方会出现「已保留自定义内容: …(点这里选用)」, 点它即可切回自定义
- 选中自定义但输入框为空时, 由宿主自己的校验拦下提交(提示请先作答), 插件不再额外拦截
- 多选题不受影响, 自定义与选项仍可并存
- 已输入的自定义内容与「是否选中自定义」会写进 localStorage, 刷新后仍在(按调用标识保留最近 64 个)

### 注入到上下文

这一项默认开启. 客户端在作答期间始终把草稿快照上报给服务端(适配器不读兜底范围 `fallback`, 只有配置页的勾选映射读它), 由服务端按这一项决定是否取用: 开启时工具到期取用最新一份, 按题随 pending 结果带回模型上下文, 每道题带自己的已选与补充; 关闭时快照只留在服务端并在调用结束时清掉.

超时说明与草稿放在同一个结果里. 带回草稿时, 说明要求模型自行判断草稿完整度并决定下一步, 判断过程不告知用户, 但要在下一步之后总结报告这次问答的决策结果.

关闭这一项后, 插件只收起卡片, 不把草稿交给模型.

### 配置项

配置页在**插件详情页顶部**的插件级配置区块, 不在「包含的组件」里. 其中「注入到上下文」与「超时后仍可回答」两个勾选可以调整, 勾选变化立即写入, 不需要保存或刷新. 页面以固定行列出「界面保留草稿」与下面三项固定特性, 只作说明, 不提供开关.

| 配置项 | 取值 | 默认值 | 界面 | 说明 |
|:---:|:---:|:---:|:---:|:---:|
| `fallback` | `ui` / `context` / `both` | `both` | 可改一项 | 超时兜底. 界面只给「注入到上下文」勾选, 勾上写 `both`, 不勾写 `ui`. 界面保留草稿恒定开启, 所以不会出现 `context` |
| `cardEnhancements` | 布尔 | `true` | 固定特性 | 只管装饰: 倒计时与警示闪烁, 单选选项的方形标号填充底色, 单选题自定义回答的单选按钮与「已保留自定义内容」提示, 提问气泡, 隐藏宿主自带的卡片等待状态与收起控件(工具行的「已继续工作, 仍可回答」不在此列, 见「超时后仍可回答」). 关闭后装饰都不出现, 但超时收尾照常: 该收的卡片仍会被收起(行级隐藏受卡片增强开关门控, 关闭增强时 `block` 的入口隐藏不生效), 草稿仍会按配置上报 |
| `infiniteWait` | 布尔 | `true` | 固定特性 | 提供「无限等待」按钮与工具栏常开开关, 关闭后两者一并移除 |
| `draftFallback` | 布尔 | `true` | 固定特性 | 超时收尾开关. 关闭后客户端不再收尾卡片也不再上报草稿, 这一轮交还宿主; 提问仍由插件按时结算 |
| `lateAnswer` | `allow` / `block` | `allow` | 可改一项 | 超时后是否保留再次回答入口. 界面给「超时后仍可回答」勾选, 勾上写 `allow`, 不勾写 `block`. `allow` 保留宿主入口与等待提示, 补交的答复作为一条用户消息送达模型; `block` 收起卡片并隐藏宿主入口, 这一轮不再接受作答 |
| `warningSeconds` | 数字 | 5 | 不暴露 | 进入红字闪烁的剩余秒数, 取值 1 至 60 |
| `timeoutSeconds` | 数字 | 120 | 不暴露 | 模型没有显式传等待秒数时用的时长, 取值 1 至 2147483; 这是本插件的默认值, 与宿主自带限时提问工具的 120 秒默认值同值但来源不同 |

最后两项不在界面暴露, 需要时在该 profile 的 `cordis.patch.yml` 里本插件行的 `config` 中写入, 例如把等待时长改成 300 秒: `config: { timeoutSeconds: 300 }`. 取值越界会在加载期报错. 三个固定特性同样只能经这条路径关闭, 例如 `config: { cardEnhancements: false }`; 该行的其余键必须一并重述, 不能只写改动的键.

## 兼容性

| 项目 | 版本 |
|:---:|:---:|
| dsh | `>=0.2.1-rc.1 <0.2.2-rc.0 || >=0.2.2-rc.0 <0.2.3-rc.1` |
| Node.js | >= 20 |

宿主 dsh 自身的 Node.js 要求以对应版本的发行说明为准.

范围写成两段是为了同时满足两种口径. 宿主自己按 `includePrerelease` 判定, 单段 `>=0.2.1-rc.1 <0.2.3-rc.1` 就够; 而 npm 与 pnpm 校验 peer 依赖时用严格 semver, 带预发布标签的版本只有在区间里出现同一个 `主.次.修订` 三元组的预发布比较器时才放行, 单段范围只点名了 0.2.1 与 0.2.3, 于是 0.2.2-rc.x 会被 peer 侧拒绝. 分成两段并在第二段点名 0.2.2 的预发布后, 两种口径接受的集合一致, 两段并集仍等价于 `>=0.2.1-rc.1 <0.2.3-rc.1`.

## 常见问题

**超时后我已经输入的内容会丢吗**

不会丢在本页. 插件会在超时那一刻把已选与已输入内容保存到内存; 宿主入口不可用时记入该提问行的气泡按钮, 可点开只读查看. 但刷新页面后这份记录会消失.

**模型能看到我写了什么吗**

看你有没有勾选「注入到上下文」. 勾选时草稿随工具结果进入模型上下文; 取消勾选时只留在界面, 模型拿不到.

**卡片为什么突然消失了**

因为这次提问超时并被插件接管. 卡片会被收起, 避免占住消息输入区又点不动. 收起之后切换会话或刷新页面都不会让它自己弹开. 默认「超时后仍可回答」是勾上的, 点提问行上的「回答」就能重新打开卡片作答; 关掉这一项后卡片不再出现且入口隐藏, 只能点提问行的气泡只读回看(超时那一刻没有任何选择与输入时不产生气泡).

**为什么我的界面上没有倒计时**

常见原因包括: 卡片增强被关掉; 这次提问是必须回答的阻塞提问, 模型传了 `-1`; 界面语言不是中文或英文; 卡片右上角的操作区找不到(宿主改版), 插件插不进自绘倒计时, 这时只留一条 console.warn. 另外刷新页面时如果卡片已经处于编辑或等待状态, 插件无法还原截止时间, 在卡片回到计时状态之前也不会显示.

**点了「无限等待」之后会怎样**

本次提问不再有截止时间, 模型会一直等, 直到你提交, 或页面与会话结束. 如果状态通道不可用, 按钮不会生效, 不再冻结, 倒计时位置显示「无法无限等待」, 这一轮交还宿主继续可作答.

**刷新页面后气泡不见了**

草稿只保存在内存里, 不做持久化, 所以刷新后本页记录的气泡与草稿都会丢. 仍在等待的提问会按宿主持久化的草稿重新评估.

**需要改我的预设吗**

不需要. 插件在每个 agent 作用域注册同名提问工具, 就近遮蔽宿主的阻塞式提问.

**会自动替我提交答案吗**

不会. 超时不会自动勾选任何选项, 也不会把草稿当成正式回答提交.

## 已知限制

**依赖宿主界面**

卡片与工具行靠宿主的类名后缀, `data-question-key`, `data-chat-call-id`, `aria-checked` 等特征定位, 宿主控件按中英文标签识别(日文的「回答」与中文同形, 因此那一项也能命中); 结算后恢复宿主入口时还会按 `查看回答` / `View answers` / `回答を表示` 认出「查看回答」入口; 工具栏开关优先按模型选择控件的无障碍标签定位, 标签不匹配时退回工具栏容器内按结构定位, 再退回全文档查找, 定位失败时按原因各留一条 console.warn 而不是静默消失. 宿主改动这些结构或文案时对应增强会失效, 识别标签与选择器集中在源码的常量文件里.

**依赖宿主提问投影**

客户端靠宿主 sessions 服务的 userQuestions 投影判断提问是否进入 continued 态, 草稿上报, 超时收尾与气泡都由它驱动. 该服务缺失或接口改名时插件按会话各打一条 console.warn: 倒计时与卡片装饰仍在, 卡片仍处于宿主等待状态时草稿照常上报并随工具结果回到模型, 但超时收尾不执行, 气泡不出现.

**会话订阅上限**

同时最多保持 8 个会话的投影订阅, 超出后最久未出现的会话降级为每秒轮询, 该会话的超时接管会延后; 轮询兜底也最多 8 个, 再超出时释放最久未出现的会话, 其超时兜底可能不再生效.

**不做持久化**

草稿只在客户端内存里, 刷新后气泡与记录都会丢. 仍在等待的提问会按宿主持久化的草稿重新评估并在满足条件时接管; 已结算的行不回显. 「已收起」这个状态另行保存在浏览器本地, 与草稿无关, 刷新后卡片仍保持收起.

**「无限等待」与草稿上报需要网页客户端**

两者共用一条带令牌的通道, 挂在宿主自己的 HTTP 服务上, 与界面同源. 页面先取令牌再上报, 令牌取不到时两个能力都不生效. 通道还会核对请求的 Host: 必须是本机回环地址(127.0.0.1 / localhost / [::1]), 或者与宿主自己公布的 origin 完全一致; 经反向代理换成别的域名访问时会被拒绝. 没有网页客户端的部署里服务端仍会按超时结算, 但草稿不会进入模型上下文, 「无限等待」也不生效.

**界面语言**

宿主 0.2.2-rc.1 起提供 8 种界面语言, 插件只识别中文与英文标签. 其他语言界面下倒计时, 无限等待按钮与工具栏开关不出现, 插件自绘的气泡与配置页文案回退英文; 超时收尾照常, 卡片仍会被收起(撤座走宿主卡片对象自己的接口, 不依赖界面文案), 宿主的「回答」入口与等待文案大多仍然可见.

**PTC 模式下受外层程序预算约束**

模型在 `run_code`(PTC 模式)里调用提问工具时, 这一轮提问的寿命受外层程序的 elapsed-time budget 约束: 预算到期时宿主硬停程序并中止在途的提问, 界面上的倒计时会中途消失, 草稿也来不及交给模型. 插件在提问期间登记外层预算, 把等待收敛到「剩余预算减去收尾余量」之内: 提问在预算到期前自己按超时结算, 草稿照常随 pending 结果交给模型, 倒计时也按收敛后的时长显示. 扣除收尾余量后可用时长不足两秒时不开卡片, 直接按预算不足报错并告知模型放宽外层预算, 不会再留下一张可作答的卡片. 「无限等待」不能突破外层预算: 冻结后的提问仍会在预算到期时结束, 只是草稿会被保留. 被中断的提问在工具行上留下只读气泡, 可回看中断那一刻的草稿. run_code 里再嵌套一层 run_code 时按内层预算收敛; 预算起点取程序真正开始派发的时刻, 前置包装造成的延迟不计入; 草稿随 pending 结果进入上下文时按单题与整轮上限截断, 截断会在同一条结果里说明, 避免超长草稿被宿主的工具结果裁剪整段吃掉.

**其他**

- 插件自行计时, 到期后由插件按超时结算并释放宿主那边的前台等待; 你在超时那一刻之前真正提交的答案优先采用
- 「超时后仍可回答」开启时(默认), 卡片仍会被收起以让出消息输入区, 宿主的「回答」入口与等待提示保持可见; 补交的答复按宿主的晚回复通道作为一条用户消息送达, 这类行不再显示插件的只读气泡
- 关掉「超时后仍可回答」后插件收起卡片并隐藏宿主入口与等待文案; 卡片增强关闭时不发生行级隐藏(装饰链路整体跳过), 此时宿主入口仍可见, 但这一轮已经收起, 点开后会被再次收起 —— 想保留超时后作答就把这一项保持开启; 同一调用被宿主重建的次数在 60 秒内超过上限(默认 5 次)后插件把座位交还宿主, 那张卡片会重新可作答; 收起记录保留 30 分钟, 或被新记录挤出(最多 128 条)后不再保持收起
- 多标签页同时打开同一会话时, 服务端按调用标识只保留一份草稿快照, 后上报的标签页会覆盖先到的那份
- 气泡里的草稿记录只保留最近 200 条, 更早的气泡不再可点开
- 宿主 0.2.2-rc.1 打开卡片时会预选带推荐标记的选项, 插件按投影里的选项原文认出这些预选值并按题整组判断: 只有选中集合与预选集合完全相同时才剥, 用户自己点过推荐项(刷新后内存里的交互登记已丢)不会被误剥成空草稿; 多选时点过任一选项后, 其余预选项按宿主自己的提交口径一并保留
- 只是点了「跳过」而没有选择与输入时, 草稿按空处理, 这次超时由插件关闭卡片
- 草稿按题合并三处来源, 优先级为宿主持久化记录, 当前显示题的实时值, 插件自己的快照; 读实时值时已选标签取的是宿主给读屏用的文案, 其中的「(推荐)」这类后缀可能被省略
- 桌面端(macOS)自 dsh 0.2.2-rc.2 起只在带 `data-window-drag` 的页头行内允许拖动窗口, 带 `data-window-drag-controls` 的容器里的控件由宿主自动排除拖动; 覆盖拖动行的自定义浮层要自身声明 `data-window-drag-exclude` 才可交互, 顶部还留了 `--dsh-frame-top-clearance` 的预留带. 插件的草稿浮层挂在 body 上, 既没有声明拖动排除也不读预留带, 因此桌面端贴近窗口顶部时可能落进预留带; 浮层内没有可点控件, 影响限于位置; 网页客户端不受影响
- 注入给模型的超时说明目前只有中文, 英文界面下模型收到的仍是中文说明
- 草稿超过单次上报上限 256 KiB 时界面显示「草稿过长, 未送达」, 这一条不计入连续失败次数, 并按固定间隔(约 5 秒)自动重试, 删减内容后会恢复上报; 超限期间模型拿到的是最后一次成功送达的快照, 可能落后于当前输入; 连续失败三次后该轮判定通道不可用, 插件不再接管, 卡片交还宿主继续可作答
- 多标签页同时打开同一会话时, 在一个页面点「无限等待」只登记到服务端, 另一个页面的倒计时照常走完, 然后按「到期未结算」把卡片还原给宿主; 模型那边不会因此结算, 内容不会丢, 只是两个页面的显示不一致

## 更新与卸载

升级时先移除旧版本再装新版本:

```
dsh plugin --profile <profile> remove dsh-question-timeout-protection
dsh plugin --profile <profile> add <新包或 tarball>
```

只想停用而不卸载时, 在该 profile 的 `cordis.patch.yml` 里按行 id 禁用:

```
- id: question-timeout-protection
  disabled: true
```

## 开发

```
pnpm install
pnpm build
pnpm typecheck
pnpm run check:translation
```

`pnpm run check:translation` 会核对三份翻译文件, 配置页字典与界面文案常量是否一致, 以及文案改动是否同步更新了维护时间.

`src/translation/*.ini` 是同一套措辞的镜像, 当前界面并不读取它: 界面文案的实际来源是 `src/constants.ts` 与 `src/client/i18n.ts`, 改可见文案要同时改这两处或其中之一与三份 ini.
